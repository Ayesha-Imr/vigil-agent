vigil

An always-on agent that lives on a small server, talks to you from the chat apps on your phone, works in the background, and interrupts you only when it is worth it. Built on pi, with its attention budget model-checked.

How it decides whether to interrupt

Every message vigil starts on its own passes one small function before it reaches your phone. The rules run in this order:

  1. Topic muted by you (/mute ci 24, or a 🔕 reaction): dropped, whatever the urgency.
  2. Same news already sent or waiting within 12 hours: dropped.
  3. Critical (harm within minutes): sent now, even at night, but at most 3 a day. Beyond that it counts as high.
  4. Low: waits for the next digest.
  5. Quiet hours: held, and sent as one message when they end.
  6. High or normal, within the daily budget and an hour since the last interrupt: sent now.
  7. Otherwise: waits for the digest. When you write to vigil first, waiting items ride along in its reply.

Promises, checked three ways

A single slip should not be able to wake you at 3 a.m. Each rule is checked by a model checker over every ordering of events, by property tests against the real code, and again at runtime, against the delivery history, right before each send.

When it acts for you

Risky actions wait for your thumb

git push, sudo, deletes, sending or paying through a connected tool: the exact command is held until you tap Approve. Each approval is single-use and expires.

A sandboxed shell

Commands run with the system read-only, vigil's own files and your SSH and GPG keys hidden, and only its work folders writable.

Untrusted pages stay data

A watched page is judged by a model with no tools at all. Work that page inspires gets read-only tools, unless you take it over.

Starts by watching

Proactive work begins in observe mode: vigil records what it would have done, and you switch it on once that looks right.

Where it lives

Telegram, Discord, WhatsApp (opt-in, unofficial), ntfy push, an HTTP endpoint for iOS Shortcuts, and a terminal, all in one conversation. Models: your ChatGPT plan through Codex (device-code login, even from your phone) and OpenCode Go, with fallback between them. From your laptop, the pi package lets any pi session hand work to vigil or ping your phone when a long run finishes.

Start

git clone https://github.com/Ayesha-Imr/vigil-agent && cd vigil-agent && npm ci --ignore-scripts && npm run build && npm link
vigil init && vigil login codex && vigil start

Then send the /pair code from the log to your Telegram bot. vigil simulate replays your own week of notices under a different policy before you change it.
